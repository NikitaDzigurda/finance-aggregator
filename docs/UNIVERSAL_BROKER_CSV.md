# Universal broker CSV v1

Формат `universal_broker` версии `1.0` предназначен для ручной загрузки
универсальной истории брокерского счёта. Шаблон находится в
`docs/templates/universal_broker_v1_template.csv`, полностью искусственный пример —
в `docs/templates/universal_broker_v1_example.csv`.

## Кодировка и структура

- кодировка UTF-8, UTF-8 BOM допускается;
- разделитель определяется автоматически: запятая, точка с запятой, tab или `|`;
- имена колонок нечувствительны к регистру, пробелам, `_` и `-`;
- обязательные колонки файла: `Date`, `Type`, `Currency`;
- пустые строки пропускаются, исходные заголовки и значения сохраняются в staging.

Поддерживаются даты `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` и ISO 8601 datetime
с обязательным часовым поясом. Decimal допускает точку или запятую, а также пробел,
неразрывный пробел или апостроф как разделитель групп. Для CSV с запятой-разделителем
значение с десятичной запятой должно быть заключено в кавычки.

## Колонки

| Колонка | Назначение |
| --- | --- |
| `Date` | Дата или timezone-aware время операции |
| `Type` | `Buy`, `Sell`, `Dividend`, `Coupon`, `Fee`, `Tax`, `CashIn`, `CashOut` |
| `Symbol` | Тикер инструмента |
| `ISIN` | ISIN инструмента |
| `Quantity` | Количество для `Buy` и `Sell` |
| `Price` | Цена единицы для `Buy` и `Sell` |
| `Amount` | Сумма для income, fee, tax и cash movement |
| `Currency` | Валюта цены или суммы |
| `Fee` | Комиссия, связанная с основной строкой |
| `FeeCurrency` | Обязательная валюта ненулевой связанной комиссии |
| `Tax` | Налог, связанный с основной строкой; используется `Currency` строки |
| `AccruedInterest` | Сохраняется и требует review при ненулевом значении |
| `Exchange` | Биржа для сопоставления ticker |
| `ExternalId` | Необязательный стабильный идентификатор источника |
| `Note` | Необязательное примечание до 1000 символов |

Знак входного числа не задаёт направление операции: направление определяется
`Type`, а в канонический payload записывается точный положительный модуль. Нулевые
необязательные `Fee`, `Tax` и `AccruedInterest` не создают отдельную операцию.

## Нормализация и сопоставление

`Buy` и `Sell` становятся `trade`, `Dividend` и `Coupon` — `income`, `CashIn` и
`CashOut` — `cash_movement`. `Fee` и `Tax` становятся отдельными каноническими
кандидатами. Поэтому одна строка сделки с комиссией и налогом создаёт три staging
rows с одним исходным `source_row_number`.

Инструмент сначала сопоставляется по ISIN. Если ISIN не найден, используется точное
сочетание `Exchange + Symbol + Currency`. Неизвестный инструмент не создаётся:
кандидат остаётся в `warning` с `instrument_match_required`. Конфликт ISIN и ticker
становится ошибкой строки. Ненулевой `AccruedInterest` не интерпретируется молча и
добавляет `accrued_interest_not_normalized`.

Preview содержит counts staging rows, число кандидатов по типам операций и точные
итоги income, fee, tax, cash in и cash out по валютам. Для сделок показывается число
покупок и продаж по валюте цены; notional не вычисляется на этапе импорта.
