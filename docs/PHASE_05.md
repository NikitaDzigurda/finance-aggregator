# Phase 05: автоматическое получение рыночных данных

## Цель и граница этапа

После импорта пользователь должен получать проверенные актуальные цены для
поддерживаемых активов без ручного ввода каждой котировки. Система сохраняет
источник, валюту и время наблюдения, обновляет оценку затронутых портфелей и
объясняет, почему цена недоступна или устарела. Ручная цена остаётся доступной.

Это следующий этап после Phase 04, выбранный пользователем 13.09.2026 и
завершённый 16.09.2026 в уточнённой границе ADR-057.
Подробный контракт: [MARKET_DATA_DESIGN.md](MARKET_DATA_DESIGN.md). Работать
сверху вниз, ставить `[x]` только после реализации и проверки. Автоматические
цены российских бумаг исключены из условия завершения: для них остаётся
проверенный ручной путь.

**Первоначальная проверка 13.09.2026:** ADR-053 фиксирует техническое
сравнение официальных кандидатов и блокер прав. MOEX требует договор для
программной обработки; OKX запрещает использование Market Data в финансовом
агрегаторе; Bybit запрещает benchmarking и не подтверждает нужные права
хранения. Повторные замеры скорости: 0 из 3 для каждого кандидата, поскольку
предполагаемое использование не разрешено. Значения скорости не придуманы.
Вместо live-адаптера подготовлены source-neutral схема цены, проверенное
сопоставление и офлайн-конвейер сохранения/пересчёта на синтетических данных.
На ту дату автоматическая загрузка и пересчёт по расписанию оставались открытыми.

**Результат 15.09.2026:** по ADR-056 включён разрешённый условиями Free
CoinPaprika общий снимок для пяти точно сопоставленных криптоактивов. Три
повторных live-замера, формат и единица USD проверены; расписание worker и
тихое обновление браузера прошли на отдельной искусственной базе. MOEX,
OKX и Bybit остаются невыбранными по указанным ограничениям, российские
акции/фонды используют ручные цены. Решением ADR-057 это принято как итоговая
граница Phase 05.

Поставленный срез: автоматическая глобальная USD-оценка пяти точно
сопоставленных криптоактивов и ручные цены для российских бумаг и остальных
активов. Источник цены выбирается отдельно от места импорта операций.
CoinPaprika выбран для криптосреза после проверки прав, скорости, охвата,
единицы и времени данных. Для прочих активов система честно показывает
отсутствие автоматической цены.
Облигации добавлять
только после отдельной проверки единицы котировки, номинала и накопленного
купонного дохода; процент от номинала нельзя записывать как цену одной бумаги.

## Условия начала

- Завершены существующие ручные цены, пересчёт позиций и P&L, FX от ЦБ,
  фоновый процесс с очередью PostgreSQL и публичный `/api/v1`.
- Не менять финансовую историю, импорт, себестоимость и правила P&L ради
  заполнения отсутствующей рыночной цены. Цена сама по себе не восстанавливает
  неизвестную себестоимость и не исправляет отрицательную позицию.
- Рабочую локальную базу и загруженные пользователем файлы сохранить. Для
  автоматических проверок использовать только изолированные тестовые базы и
  искусственные данные.

## 1. Уточнить контракт источников и единиц измерения

- [x] Сравнить официальные источники для российских бумаг и криптоактивов:
  Московскую биржу ISS, Bybit Spot и OKX Spot. Проверить право использования
  данных для автоматического расчёта, охват, задержку публикации, валюту и
  единицу цены, доступность общего снимка, размер ответа, частоту запросов и
  повторные замеры разрешённого выбранного источника в рабочем окружении. Для
  кандидата с договорным запретом не выполнять запрещённый benchmark, а
  зафиксировать ограничение. Место импорта не должно заранее определять
  источник цены. Выбор и причины записать в `docs/DECISIONS.md` до адаптера.
- [x] Не использовать парсинг страниц или неофициальные интерфейсы TradingView
  как источник цен. Вернуться к нему только при наличии документированного
  доступа и прав на автоматическое использование данных. Если ни один
  кандидат не разрешает нужный способ работы, зафиксировать препятствие и
  оставить ручные цены вместо сомнительного обхода.
- [x] Зафиксировать, что именно означает цена каждого поддерживаемого класса:
  одна акция/пай в валюте торгов; одна криптоединица в USD. Отличать последнюю
  сделку, индексную оценку и цену закрытия. Не выдавать одно за другое.
- [x] Проверить происхождение времени котировки. Отдельно хранить время данных
  источника и время получения; время ответа сервера не называть временем
  последней сделки. Зафиксировать признак качества времени.
- [x] Уточнить поддерживаемый тип и поведение вне торговой сессии. CoinPaprika
  даёт круглосуточную глобальную агрегированную оценку, не цену торговой
  площадки. Российские бумаги и облигации остаются ручными; облигационный
  процент от номинала не включать без отдельной методики.

**Готово, когда:** для каждого включённого типа цены есть документированное
соответствие «поле источника → цена одной единицы → валюта → время», а
неподтверждённые случаи перечислены как неподдерживаемые.

## 2. Сопоставить внутренние инструменты с внешними кодами

- [x] Ввести явное сопоставление `instrument ↔ provider + market/board + symbol +
  quote currency` с уникальными ключами, источником подтверждения и состоянием
  `verified/ambiguous/unsupported`. Не сопоставлять по одному названию или
  неоднозначному тикеру.
- [x] Для включённого CoinPaprika-среза проверять точные `coin_id`, имя,
  canonical `crypto_asset_code`, тип и USD; повторно используемый инструмент
  из разных счетов имеет одно глобальное сопоставление. ISIN и режим торгов
  обязательны перед будущим автоматическим адаптером российских бумаг, но
  ручной путь Phase 05 их не подменяет.
- [x] Проверить конфликтующие, устаревшие и переименованные коды. Искусственные
  демонстрационные активы не сопоставлять с реальными активами по похожему имени.
- [x] Добавить безопасный просмотр причин несопоставления в `/api/v1`; при
  неоднозначности оставить ручную цену, не угадывать.

**Готово, когда:** ни одна котировка не попадает на актив только из-за
совпадения названия/тикера; неподдерживаемые активы видны пользователю.

## 3. Сохранить точные наблюдения и выбрать цену

- [x] Мигрировать текущую таблицу `market_prices`, где разрешён только
  `source='manual'` и уникальность не учитывает поставщика. Сохранить все
  существующие ручные строки и совместимость публичного ручного ввода.
- [x] Добавить поставщика, вид цены, валюту, время наблюдения, время получения
  и происхождение времени; числовые значения оставить `Decimal`/`NUMERIC` и
  JSON-строками. Для повторного получения той же котировки обеспечить
  идемпотентность, для изменённого значения с тем же ключом — явный конфликт.
- [x] Выбирать только наблюдения `observed_at <= valuation_as_of`, в нужной
  валюте и с проверенной единицей измерения. При равном времени ручная цена
  имеет приоритет; при разных временах выбирается более позднее проверенное
  наблюдение. Порядок разрешения ничьих должен быть детерминированным.
- [x] Не объявлять цену свежей только из-за нового времени загрузки. Явно
  различать сбой источника, неподдерживаемый актив и устаревшую цену.
  CoinPaprika не имеет состояния закрытой сессии; этот статус понадобится
  будущему биржевому адаптеру. Состояния `complete/partial/unavailable` сохранить.

**Готово, когда:** старые ручные цены читаются без изменения, новые записи
воспроизводимы, а цена из будущего не влияет на прошлый срез портфеля.

## 4. Добавить получение данных в существующий фоновый процесс

- [x] Расширить типы заданий и ограничение `import_jobs` для общего задания
  обновления рыночных цен без `batch_id`. Для первого среза использовать
  существующий worker и PostgreSQL; отдельную инфраструктуру добавлять только
  по результатам замера нагрузки. Приватный API не использовать.
- [x] Реализовать ограниченные по времени публичные запросы к проверенным
  адресам поставщиков. Получать общий снимок рынка/площадки и сопоставлять
  активы локально; не отправлять наружу портфель, счета, файлы, количества,
  идентификаторы пользователей, импортированные операции и список позиций.
  Поштучные запросы по активам пользователя не входят в первый срез.
- [x] Добавить защиту от ошибок ответа, пустых полей, нулевых/отрицательных
  цен, смены формата, неполного результата, повторов, ограничения частоты и
  сетевых сбоев. Не заменять последнюю корректную цену повреждённым ответом.
- [x] Не сохранять всю полученную биржевую сводку: после проверки оставлять
  наблюдения только для однозначно сопоставленных инструментов, нужных
  действующим портфелям. Оценить ожидаемый рост таблицы при выбранной частоте,
  определить срок хранения с учётом ссылок из расчётных снимков и измерить
  время загрузки/сохранения/пересчёта на искусственном большом наборе.
- [x] Ввести настраиваемый интервал обновления, запрет параллельных одинаковых
  заданий и журнал результата без сырых пользовательских строк. Как и у FX,
  автоматическую постановку отключать в тестовом режиме и `--once`.
- [x] После новых пригодных наблюдений пересчитывать только затронутые
  портфели через прикладной интерфейс; обеспечить ограничение нагрузки и
  повторяемость. Сбой пересчёта отображать отдельно от успеха загрузки цен.

**Готово, когда:** постоянно работающий локальный worker сам обновляет
поддерживаемые цены и оценку без кнопки пользователя; повторное задание не
создаёт дубликатов; сбой одного источника не останавливает другой. Выбранная
частота и объём хранения подтверждены замером, а не предположением.

## 5. Обновлять стоимость без действий и ожидания пользователя

- [x] Запускать получение и пересчёт автоматически по расписанию. При входе
  в портфель сразу показывать последнюю сохранённую оценку; не блокировать
  экран ожиданием внешнего источника и не требовать нажатия «Обновить».
  После фонового пересчёта обновлять видимые данные без навязчивых уведомлений.
- [x] Сохранить в `/api/v1` источник, вид цены, валюту, время данных и
  получения для проверки расчёта. Подробные счётчики принятых/пропущенных
  котировок и причины ошибок держать в безопасной диагностике, а не выводить
  таблицей на основной экран.
- [x] На основном экране показывать стоимость и, когда нужно, короткую пометку
  «цены на …» или «часть цен недоступна». Причину по конкретному активу
  раскрывать только в его деталях либо по явному запросу; технические коды,
  виды цен и два разных времени не показывать всем постоянно.
- [x] Если цена действительно отсутствует и пользователь может помочь,
  предложить существующий ручной ввод. Не предлагать ручной запуск всей
  синхронизации как обычное действие. Объяснение связи цены и неизвестной
  себестоимости показывать только у затронутого неполного P&L.
- [x] На фронте обращаться только к `/api/v1`, обновить сгенерированные типы
  и не считать стоимость, курс или P&L в браузере.

**Готово, когда:** пользователь без кнопки и ожидания видит последнюю
доступную оценку, а после фонового обновления — новую; детали источника
доступны при необходимости, но не перегружают основной экран.

Подготовительная браузерная проверка на искусственном смешанном портфеле
подтвердила немедленный показ сохранённой оценки, 30-секундное тихое обновление
после синтетической записи цены и серверного пересчёта, детали происхождения,
отсутствие оценки для неподдерживаемых активов и сохранение `null` у
себестоимости/P&L при известной новой стоимости. На подготовительном прогоне
настоящее расписание и live-ответ поставщика не проверялись; они проверены
отдельным сценарием 15.09.2026 ниже.

15.09.2026 повторный live браузерный прогон на новой временной базе показал
немедленную сохранённую оценку 31 USD и автоматическое обновление после
CoinPaprika без кнопки. В счётчиках фонового задания: 2 новые цены, 3 неиспользованных
котировки, 1 пересчитанный портфель, 0 ошибок. Неизвестная себестоимость осталась
`null`, неподдерживаемая монета не получила цену, ошибок консоли не было.
В том же портфеле подтверждён искусственный four-document Bybit Spot CSV bundle:
26 операций, позиции QAX и QAY видны в браузере и не получают выдуманной цены.
Тестовая база и файловое хранилище удалены после проверки.

14.09.2026 на отдельной временной PostgreSQL-базе проверены `0017` вверх/вниз,
14 финансовых/API-сценариев, включая неверные валюту, единицу и вид цены,
идемпотентный повтор, конфликт неизменяемой котировки и повтор пересчёта после
сбоя. Новый детальный путь «Почему нет цены» проверен в браузере на
искусственном инструменте без сопоставления. Это не проверка live-поставщика,
рыночной сессии, состава исходящего HTTP-запроса или планировщика: для них
пункты остаются открытыми.

## Что не входит

График исторической стоимости портфеля, поток цен в реальном времени,
инвестиционные рекомендации, торговые поручения, приватные API брокеров/бирж
в рамках этой фазы, прогноз доходности и попытка оценить любой неизвестный
актив по похожему названию. Новые цены не меняют записи Ledger и не дорисовывают
несуществующую историю приобретения. Read-only account connectors запланированы
отдельно в Phase 06.

## Передача в Phase 06

Phase 05 продолжает ежечасно накапливать append-only CoinPaprika observations
для присутствующих в портфелях активов из пяти проверенных криптоактивов. Это
основа будущей исторической аналитики,
но само наличие ряда цен ещё не доказывает полноту истории портфеля: нужны
операции, исторический FX, corporate actions и известная себестоимость.

Следующая фаза описана в [PHASE_06.md](PHASE_06.md). В ней приватный read-only
API используется для получения личных исполнений, комиссий, движений и
контрольных остатков конкретного счёта. Публичный pricing остаётся отдельным:
не следует получать пользовательские позиции ради котировки или использовать
один администраторский брокерский/CEX-аккаунт как общий источник для других
пользователей. Provider positions служат сверкой и не перезаписывают Ledger.
